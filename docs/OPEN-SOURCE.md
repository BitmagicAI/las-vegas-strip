# Open-sourcing Las Vegas Strip: audit, decisions and release checklist

Prepared 2026-10-22 at the owner's request. The owner wanted:

- the project open for contributions, and free for anyone to use as the setting of their own game;
- Bitmagic as the supported path, with other engines left to their users;
- bookkeeping of what is ready and what is missing;
- instructions an AI agent can follow to pick up a task;
- a way to show who is working on what;
- an open licence that asks for attribution.

Nothing has been committed, pushed, uploaded or published. A local `git init` exists with no commits.
The owner answered the open decisions the same evening (below).

## Audit findings

**Secrets.** None found in the files git would commit (keys, tokens, private keys, assigned secrets).
`tools/uthana/launch.sh` used to source a `.env` from another project. It now takes `UTHANA_ENV_FILE` from the
environment, and no credentials are in the repository.

**Machine paths.** 37 tools hard-coded paths under the owner's home folder: the CLI's Chrome launcher and Playwright,
uv's Python 3.12, the `bitmagic` binary, Uthana and the character forger. All now resolve at run time through
`tools/lib/bitmagic-cli.mjs` and `tools/lib/paths.py`, or through arguments and environment variables. Records and logs
in `docs/project-records/` still mention home-folder paths (about 35 files, harmless).
`python3 tools/release/check-public.py --fix-paths` rewrites them to `<repo>/` and `~/` before release.

**Size.** The committable set is about 2,980 files and 163 MB (without `engine/` and the CLI skills). No file exceeds 50 MB. The largest are:

- `public/foliage/tree-0.glb` (28 MB);
- `public/foliage/bellagio-placements.json` (13 MB);
- `src/work/characters/animations/npc-idles.json` (11 MB);
- nine character GLBs (about 6 MB each).

`build/` (about 29 GB) is excluded. The game needs 1,345 files from it (1.1 GiB), tracked with Git LFS in
`runtime-assets/` (decided 2026-10-23); a release snapshot of the same set is optional.

**Kept out of the repository (`.gitignore`):**

| What | Why |
|---|---|
| `build/` | Built assets and intermediates; the runtime part is mirrored into `runtime-assets/` (Git LFS) |
| `.bitmagic/` | CLI state, verify output, film recordings, the info video, the pack itself |
| `docs/project-records/archive/`, `user-references/`, `index-history/`, and every image, PDF, video, GLB and `.blend` under `docs/project-records/` | Owner screenshots, Google Earth captures, public photos and floor plans: research material that is not ours to redistribute. The records keep their URLs. |
| `**/references/**` images and PDFs (e.g. `tools/resort-blocks/references/`) | Same |
| `tools/info-video/fonts/` | Apple's SF Mono, which may not be redistributed |
| `tools/uthana/adapter/`, `tools/optimize/bm-tools/`, `tools/foliage/sources/` | Third-party code and tool installs; rebuilt locally (`tools/optimize/setup-tools.sh`) |
| `.claude/settings.local.json`, `.env*`, `*.pem`, `*.key`, `.npmrc`, `.venv/`, logs, `.DS_Store` | Local machine state |

**Map and imagery provenance.**

- Geometry comes from OpenStreetMap (Overpass API; ODbL) and the Clark County GISMO Pavement service. The county's
  layers are downloaded at build time and never shipped: only the road, sidewalk and median surfaces derived from them
  are (decided 2026-10-26; NOTICE.md).
- Cesium and Google Earth were used for viewing and coverage checks only. No Google 3D Tiles geometry or imagery is in
  any output.
- Textures are drawn by the project's scripts, are CC0 Poly Haven scans, or are originals generated from text prompts
  alone (the Venetian interiors' frescoes, skies, carpet, panels, shop windows and slot screens; prompts in
  `docs/project-records/venetian-interiors-2026-10-23/generated-images.md`).
- The gomeasure3d Statue of Liberty scan (CC BY 4.0) ships adapted (decimated) as New York-New York's statue, credited in NOTICE.md and on screen.

**Brands.** Signage text names real casinos and tenants. NOTICE.md carries a non-affiliation and trademark notice.
`tools/film/brand/bitmagic-logo-white.png` is Bitmagic's own logo, used in the film titles.

## Decisions (the owner's answers, 2026-10-22)

1. **The engine is not included.** It is a dependency: `bitmagic upgrade` installs it, which needs a Bitmagic Pro
   subscription. `.gitignore` excludes `engine/` and the CLI's skills, and README.md, CONTRIBUTING.md and AGENTS.md
   say how to install them. `upgrade` only installs the currently published engine, so this repository must follow
   it (task `rel-engine-current`, done on 2026-10-24: engine 3.1337).
2. **GitHub** hosts the repository. The runtime set is in Git LFS: on 2026-10-23 the owner moved it there from a
   release asset so that models can change in pull requests, and upgrades the GitHub plan for the LFS traffic.
3. **The licences apply to the Vegas project only.** They cover the code (MIT), the original content (CC BY 4.0) and
   the OpenStreetMap-derived data (ODbL). They do not cover the engine, the CLI or its skills, or third-party material.
4. **The zombie game moves to a separate project** that shows one kind of game built on the city data. See below.
5. **Journals stay out.** `.gitignore` excludes `docs/project-records/journal-*.md`. Four technical reports also
   quote the owner word for word, a line or three each:
   - `idle-performance-2026-10-07`;
   - `interior-performance-2026-10-07`;
   - `lighting-analysis-2026-10-08`;
   - `showcase-video-2026-10-08`.

   Those lines were paraphrased on 2026-10-22, labelled "summary". The originals stay in the local journals.
6. **The map carries a minimal set of game-specific material.** That governs the split below and the `world.json`
   cleanup.
7. **Repository:** `BitmagicAI/las-vegas-strip` on GitHub (https://github.com/BitmagicAI/las-vegas-strip), created by the owner on 2026-10-23, private
   until the release checklist passes. The city is called "Las Vegas Strip"; "Vegas: Afterlight" stays the zombie
   game's name.
8. **Source pack (open):** whether to publish the roughly 10 GiB of build sources. These are the original GLBs,
   Blender scenes and survey data the builders read. Without them, contributors can change code, records and anything
   a builder makes from scratch, but cannot rebuild most existing buildings (task `tool-source-pack`).

## Splitting out the zombie game (done 2026-10-22)

The owner approved the plan on 2026-10-22, and it was carried out the same night. A backup of the state before is in
`GitFork/_backups/vegas-afterlight-2026-10-22-pre-split/`.

**The hook.** `src/work/GameLayers.ts` defines `GameLayer` and `GAME_LAYERS`:
- `load` receives the player, HUD, ground and nearby lights;
- `filmReady` lets a layer offer film scenarios;
- `tick`, `update`, `render`, `setRenderVisibility`, `setStreamingHeld` and `dispose` cover the rest.

`Game.ts` runs every listed layer and has no other knowledge of a game. The city lists none.

**Moved out of the city** (into `GitFork/vegas-afterlight-game`, which registers `src/work/afterlight/AfterlightGame.ts`):
- the survival layer: `AfterlightLevel.ts`, `Sanctuary.ts` and `vegas-missions.json`. The Paris lift's three positions
  now live in `src/work/paris-lift.json`;
- `src/work/characters/` (cast, NPC activities, nine characters, Uthana animations);
- the storm-chase film scenes (`film/SceneSession.ts`, `SceneControls.ts` and the arsenal, crowd, ragdoll, driver and
  audio files);
- 15 tests, the storm and driver tools, `tools/uthana/`, the character tools and skills, `character-review.html`,
  `docs/HERO-CHARACTER-BRIEFS.md` and `docs/WORLD-PLAN.md`;
- from `world.json`: six wrecked taxis on the Strip, the slot machine and the nine character rows;
- from the jeep: the sanctuary charger and battery.

The zombie-era `GAME-DESIGN.md` and `mechanics-plan.md` went to `docs/history/`. The city has new ones.

**Stayed:**
- `GroundSurfaceIndex.ts`, now in `src/work/`;
- the film director;
- time of day and weather, in the new `film/FilmLook.ts`, which the game's car-chase session reuses;
- the jeep, doors, the lift, the coaster and the Sphere.

**Verified:**
- **City:** `bitmagic check` passes, and all 15 logic tests pass (brought up to date on 2026-10-26). The
  smoke test passes: four hotel rooms, three venues, the Sphere and the coaster, with no failed requests and no errors.
  A rain take records correctly through `FilmLook`.
- **Game project:** `bitmagic check` and the smoke test pass. Its layer loads the nine characters and the sanctuary.
- **Committable city:** 2,792 files, 70 MB.

**Left** (task `rel-split-game-layer`):
- the city's own game id and the renaming, once the name is chosen;
- git wiring between the two repositories after the city's first commit;
- both projects moving to the current engine (`rel-engine-current`).

## Release checklist

1. Settle the decisions above, and update NOTICE.md and the licence files (the repository URL is in).
2. `python3 tools/release/check-public.py --fix-paths`, then `python3 tools/release/check-public.py`. It must exit 0.
3. `python3 tools/resort-blocks/review.py` and `python3 tools/tasks/build-board.py`.
4. `python3 tools/release/asset-pack.py stage` and commit `runtime-assets/`, then `node tools/release/cdn-upload.mjs`
   for the published game (published privately, unlisted, on 2026-10-24: https://bitmagic.ai/games/PVEF9G6NJIJ6/). Optionally `build` a release snapshot,
   upload it and set `pack.url` in `tools/release/asset-pack.json`.
5. Test a clean clone on a second machine or folder:
   - `bitmagic login` (Pro) and `bitmagic upgrade`;
   - `pnpm install` (it copies the runtime set into `build/`);
   - `bitmagic check`;
   - `bitmagic dev`;
   - `node tools/release/smoke-clone.mjs --shots`. It covers four hotel rooms, three venues, the Sphere and the
     coaster, and fails on a missing file or a page error.
6. First commit, and push to the public repository.
7. Then create the labels and issues with `node tools/tasks/sync-issues.mjs --apply` (in batches of about 50).
8. Enable GitHub Actions. The claim workflows need only `issues: write`, which they declare themselves.
9. Turn on branch protection for `main` (pull requests, one review).
