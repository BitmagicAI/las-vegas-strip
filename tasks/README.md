# Tasks: what to work on, and how to say you are on it

Everything still to do in the city is listed in [BOARD.md](BOARD.md) and, machine-readable, in
[index.json](index.json). [STATUS.md](../STATUS.md) gives the overall numbers. All three are generated by
`python3 tools/tasks/build-board.py` from the project's own records, so they stay true to the code:

| Source | Becomes |
|---|---|
| `tools/resort-blocks/<block>.json` (188 blocks, listed in `queue.json`) | one `ext-<block>` task. Its items are the record's `remaining` list, or the open issues and pending gates of a seven-gate record. |
| `docs/project-records/city-exteriors-2026-10-12/inventory.json` (631 mapped buildings) | attached to their block. Buildings no block covers become `site-<owner>` tasks. |
| hotel sets and authored venues (constants in `build-board.py`) | `int-<resort>` tasks: casino resorts without a public interior built to plan |
| [curated.json](curated.json) (edited by hand) | release, tooling, performance and film tasks |

Never edit `index.json`, `BOARD.md` or `STATUS.md` by hand. Change the record, then re-run the generator.

## Claiming: one task, one person

Each task has a GitHub issue titled `[task-id] Title`. **The issue is the lock.** Its assignee is the person working on
it, and the `claimed` label is set while it is held.

1. **Find one.** `node tools/tasks/pick.mjs` lists open, unclaimed tasks, best first. Filter with `--area exteriors`,
   `--size S,M`, `--limit 30`. It reads the claims through the GitHub CLI (`gh auth login` once).
2. **Read it.** `node tools/tasks/pick.mjs show <task-id>` prints the full brief: what to do, the record, which scripts
   build it, the files you will touch, and when it counts as done.
3. **Claim it.** Comment `/claim` on the issue, or run `node tools/tasks/pick.mjs claim <task-id>`. The `claim`
   workflow assigns you. It refuses if someone else holds the task, or if you already hold two.
4. **Show progress.** Create branch `task/<task-id>` and open a **draft** pull request early, with `Closes #<issue>` in
   its description. Push at least every few days.
5. **Finish or let go.** Mark the pull request ready for review when the "Done when" list is met. If you stop, comment
   `/unclaim`.

**Stale claims are released.** A claim with no human comment and no pull-request activity for 14 days gets a reminder.
After 21 days it is released automatically (`.github/workflows/stale-claims.yml`). Tasks marked "maintainers only" need
accounts or decisions outside the repository. The claim workflow will not assign them to contributors.

**Two tasks that touch the same files** (the same block record or the same builder script) should not run at once.
`show` lists the files. If another open pull request already changes them, pick something else or coordinate on the
issue.

## Working on a task with an AI agent

Clone, fetch the assets ([docs/ASSETS.md](../docs/ASSETS.md)), then tell your agent:

> Read AGENTS.md and CONTRIBUTING.md. Run `node tools/tasks/pick.mjs`, choose a small open task, claim it with
> `node tools/tasks/pick.mjs claim <id>`, and do it on branch task/<id>. Follow the task's "Done when" list and open a
> draft pull request early.

The agent instructions in [AGENTS.md](../AGENTS.md) and [CONTRIBUTING.md](../CONTRIBUTING.md) spell out the rest: the
performance rules, how to verify, and what may not be committed.

## Sizes and priorities

- **S** is one or two items, typically an afternoon. **M** is three to five items. **L** is six or more, or a whole
  interior.
- **P1** is release-blocking, or the central Strip resorts (the first twelve blocks of the queue). **P2** means close to
  the Strip or tall. **P3** is everything else.

## Proposing a task

Open a "Propose a task" issue. A maintainer either adds it to `curated.json` or starts a block record for it in
`tools/resort-blocks/` (copy a lightweight record such as `akita-plaza.json` and add it to `queue.json`), then re-runs
the generator and `node tools/tasks/sync-issues.mjs --apply`.

## Maintainers

- After records change: `python3 tools/tasks/build-board.py`, then `node tools/tasks/sync-issues.mjs` (dry run), then
  `--apply`. Sync creates missing issues, refreshes changed ones, and closes issues whose task has left the board.
- To refresh the hotel-set and venue constants in `build-board.py` from a full checkout:
  `ls build/hotels/*-room.glb` and the `venues.json` files under `build/strip-landmarks/` and `build/resort-blocks/*/`.
