# Bellagio mapped exterior — local build and review

Status: mapped exterior plus north lakefront reconstruction installed, 2026-10-05. See `bellagio.json` for sources,
confidence limits, unfinished components and acceptance gates. This is not a
complete architectural reconstruction. The creator allowed a later refining pass.

## Inputs and ownership

- Existing survey: `build/strip-survey/survey.json` (OSM extract; north-up source
  coordinates are converted by `tools/strip-landmarks/common.py`).
- Existing city surfaces and bridge planning: `build/geographic-strip/`.
- Detailed legacy casino: `build/geographic-strip/detailed.glb` and
  `src/work/geographic/level.json`; original owner classifier uses the staged
  hotel mesh-level source identified by `tools/geographic-strip/mapping.py`.
- Bellagio official PDF and rendered map: `tools/resort-blocks/references/bellagio/`.
- Retained custom guest modules: existing hotel streaming data. Their complete
  official-floor-plan registration remains unfinished.

`build_bellagio.py` replaces only explicit OSM IDs. `install_bellagio.py` removes
legacy outside batches and their obsolete collisions; it retains custom casino,
service rooms, guest templates and unrelated buildings. Local originals are backed
up once under `build/resort-blocks/bellagio/before/`. This directory is not archived
as research and is ignored by Git.

## Rebuild sequence

Use the project's Python environment with NumPy/Shapely installed, and Blender.
Existing local examples use `PYTHONPATH=build/south-strip/python` and the bundled
Python. These are local dependencies, not a portable lockfile. Start or reuse the
local Bitmagic dev server first per AGENTS.md.

1. `python tools/resort-blocks/build_bellagio.py`
2. `blender -b --python-exit-code 1 --python tools/resort-blocks/export_bellagio.py`
3. `python tools/geographic-strip/rebuild-buildings.py`
4. `python tools/resort-blocks/cut_bellagio_lake.py`, then
   `python tools/geographic-strip/compact_collision.py`
5. `blender -b --python-exit-code 1 --python tools/geographic-strip/export_city.py`
6. `python tools/resort-blocks/install_bellagio.py`
7. `node --experimental-loader ./tools/geographic-strip/test-loader.mjs tools/resort-blocks/test-bellagio.mjs --city`
8. `blender -b --python-exit-code 1 --python tools/resort-blocks/render_bellagio.py`
9. Run `bitmagic check`, `bitmagic verify`, `bitmagic reload` with the actual
   creator request supplied as each command's `--original-prompt`.
10. Review in-game, update `bellagio.json` and the dated project journal, then run
    `python3 tools/resort-blocks/review.py` and
    `python3 tools/archive-project-records.py`.

The full geographic install pipeline also reapplies the Bellagio selective
installer when its generated version exists. There is no upload/publish step.

The lakefront uses `bellagio_lakefront.py`, the preserved OSM water boundary
`references/bellagio/lake-outline.json` (way/22971030), the creator's aerial and
JERDE's waterfront photograph / rotunda drawing. These are visual references;
all in-game textures are original procedural material maps. Plan geometry uses
the existing spherical Mercator local approximation (R=6378137, origin −115.173,
36.116). Facade heights, roof pitches, water elevation −1.1m and planting are
fitted estimates. Fountain hardware is an interpretation, not an engineering plan
or a functioning fountain show.

After changing bridge passages, run the existing `tools/geographic-strip/build-access-only.py` before the
Bellagio generator. `cut_bellagio_lake.py` is idempotent and `prepare.py` reapplies
it on a full geographic rebuild. Its separate collision and visual cuts prevent
terrain from filling the lake. The sanctuary was moved from (−51,290), inside the
water boundary, to dry ground at (−60,540). The target is recorded in `mapping.py`.
For an existing installed detailed GLB, `relocate_bellagio_sanctuary.py` updates
only sanctuary-owned meshes/colliders/anchors and nearby spawn. It is idempotent;
run it before the selective Bellagio installer. Keep the jeep and charger with
the sanctuary rather than placing their original anchors in the lake.

## Towers (2026-10-08 remodel)

The main tower and the Spa Tower are generated by `bellagio_towers.py`, called from `build_bellagio.py`. They follow
the owner's Google Earth view (`docs/project-records/bellagio-remodel-2026-10-08/`). Each tower has three segments
(cream lower, white band, cream middle of eight square rows, white belt, white crown with arched windows), lower
pyramid-roofed end pavilions at the surveyed split vertices, and patina hip roofs. The main tower's rotunda rises to
the 155.8 m tip; its main roofline is 134 m. Colours and finishes live in `bellagio_palette.py`, which the export
reads. The Spa's visuals use source `tower/way/114716301` in the exterior; its collision stays in
`build/highrises/bellagio-spa-collision.json`, and `HighriseCity` drops the old generic Spa visuals
(`DRAWN_ELSEWHERE`). For quick iterations without the game:
`python tools/resort-blocks/preview_bellagio_towers.py`, then
`blender -b --python tools/resort-blocks/render_bellagio_towers.py -- reference lake spa rotunda`.
For in-game stills through the film camera:
`node tools/probe-eval.mjs build/film/look/bellagio/look.js --storage 'afterlight:film=1' --viewport 1600x900 --out build/film/look/bellagio`.
After an export, run `node tools/optimize/optimize-runtime-glbs.mjs --only=resort-blocks/bellagio/`, then the same
command with `--variant=webp-textures`, then `node tools/optimize/install-optimized.mjs --only=resort-blocks/bellagio/`.
Until then the game loads the new original.

## Runtime review

Current local server: `http://localhost:3090/`.
Use `?resortReview=1&landmark=bellagioBlock` for the local walkthrough controls.
The resort dropdown includes arrival, lobby, pools, conservatory and promenade.
“Visit level” and “Pool view” move to authored inspection positions. “Walk forward
5 seconds” uses normal movement input. Teleporting is inspection only and is not
proof of a connected route. “Stair ascent” is currently authored for Cosmopolitan,
not these Bellagio areas. Leave this limitation visible until reviewed properly.

The static route test checks a standing capsule and floor support at 30cm intervals
through the new routes, with city, retained interior and Via Bellagio collision.
It does not prove closed-door traversal, stair/guest loading, all return routes,
accessibility grades or performance. The earlier first-pass audit had 2,200 samples.

Lakefront review adds “Lakefront aerial”, “Lake promenade”, “Bridge entry” and
“Bridge stairs”. The aerial is an inspection bookmark: toggle the engine's F6
flying mode before visiting it, then turn flying off for walking checks. The
combined audit now includes all eight Via Bellagio route sections and the lake
promenade, with 3,993 standing-capsule/floor samples. Run `test-access.mjs --city`
as well to retain all other bridge checks. Neither test proves doors open.

Default Blender review renders only the two waterfront views; pass `-- --all`
to also render arrival, patio, pool, lobby and overall aerial. Neutral renders
omit the separately owned city and access meshes; in-game captures are the
integration evidence. The oversized U-shaped bridge enclosure has been removed,
and its eastern descent now runs to the Strip-side lower landing, with a clear
lower exit. Existing upper gallery doors remain interactive.

Runtime footage, exported-mesh renders, warm frame samples and final CLI results
are preserved under `docs/project-records/archive/build/resort-blocks/bellagio/`.
Cold-load and memory acceptance are still open. Offline neutral-daylight renders
are labeled separately from actual game captures.

## Selective lake-edge repair (2026-10-09)

For lake-bank overlaps / the missing roadside cross-section, use
`repair_bellagio_lake_edge.py` on the current cached exterior rather than rebuilding
towers, ramps, trees and interiors. It cuts only shared bank/promenade/garden faces,
submerges the fountain hardware and closes the city cut along x=-22. The narrow
retained verge gets collision at its existing visible height. The full builder
also invokes `bellagio_edge_ownership.py`, so the repair survives regeneration.

Export one asset with Blender:
`--python tools/resort-blocks/export_bellagio.py -- --only bellagioBlock-exterior`.
Optimize both variants and install using
`--only=resort-blocks/bellagio/bellagioBlock-exterior`. No city export or selective
world installer is needed for this repair. The cached repair preserves the
runtime collision's appended canopy when adding source collision.

clipping test, and the real browser `probe-bellagio-water.js` through probe-eval.
